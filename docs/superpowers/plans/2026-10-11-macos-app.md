# MediaInfo QuickLook implementation plan

Goal: Deliver a runnable native macOS menu bar application and reproducible Xcode project.
Spec: ../../HANDOFF.md (user supplied, implementation explicitly authorized).
Architecture: SwiftUI window, AppKit table and menu bar, AVKit player, Carbon registered hotkey, Finder Apple Events. Non-sandboxed developer app with Automation entitlement. Metadata core independent of UI; SwiftPM and Xcode compile the same sources.
Minimum macOS: 13. No network analysis or video modification. Transfer tags alone determine HDR classification. Space is never registered.

1. Core: tests first for HDR tags, JSON main-video selection, rational rates, CSV escaping and cache invalidation; implement MediaMetadata, ProbeService and MetadataCache. Run swift test.
2. Platform feasibility: FinderSelection.selectedURLs checks frontmost Finder and returns AppleScript list values; GlobalHotKey registers/removes Option-Space and reports OSStatus conflicts. ffprobe real synthetic MP4 and AVPlayer probe. Record TCC/UI limitations truthfully.
3. App: bounded concurrent scanning, cancellation, native sortable table, persistent column preferences, filters/search/counts, TSV/CSV, preview and settings. Build and launch .app using installed CLI SDK.
4. Delivery: checked-in Xcode project, scripts for Debug/Release .app and ZIP, README, synthetic integration suite including 200 inputs, verification report and screenshots if capture is available.

Review focus: nil/unknown transfer never SDR; cover images excluded; hostile filenames passed as arguments; cancellation reaps child processes; stale scan results cannot overwrite a new selection; export quotes/newlines preserve cells. Real camera and HDR-display acceptance is separate from synthetic tests.

Execution: parallel independent core/platform components using dispatching-parallel-agents; primary integrates UI and builds. No shared-file edits. Final independent review and full test run.
