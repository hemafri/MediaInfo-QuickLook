# MediaInfo QuickLook — Codex 开发交接文档

版本：v1.0（开发启动基线）

状态：需求与技术方案已明确；**尚未编写、编译或验证应用**。

## 0. 交给 Codex 的执行指令

请在当前 macOS 开发环境中创建并实现名为 **MediaInfo QuickLook** 的可构建原生 macOS 项目。不要只做原型图、伪代码或计划；应逐步提交工程源码、测试、README、打包步骤及验证结果。优先实现可用的 MVP，再扩展列表功能。请自主排查编译与运行错误；只有遇到无法通过环境或系统权限解决的外部阻碍时才记录阻碍及明确的手工验证步骤。不要声称未实际运行过的功能已经通过测试。

## 1. 产品定位与目标用户

面向同时使用 **Sony 索尼**、**Nikon 尼康** 相机，在 macOS Finder 中管理 MP4/MOV 视频素材的用户。核心问题：快速核验每个视频标记的 SDR/HLG/PQ 类型，以及色彩原色、传递函数、位深、编码、帧率等参数；无需进入剪辑软件。

**首要使用体验：**
- `Space`：继续使用 macOS **系统原生** Quick Look；不被本工具拦截或替换。
- `Option + Space`（默认，可修改）：对 Finder 当前选择打开 MediaInfo QuickLook 增强窗口。
- 选择 1 个受支持视频：单文件播放与参数展示。
- 选择多个视频：一个可排序、筛选的批量参数窗口，并可双击进入单文件预览。
- 菜单栏入口随时禁用快捷键、暂停增强预览或退出；退出后原生空格预览完全不受影响。

## 2. MVP 必须实现的功能

### 2.1 Finder 集成和快捷键
- 菜单栏常驻应用，提供：打开窗口、启用/停用快捷键、自定义快捷键、设置、退出。
- 注册默认 `Option + Space` 全局快捷键；启动时检测冲突，提供可修改快捷键及相应提示。
- 触发后获取 Finder **当前所选文件 URL 列表**，尽量保持 Finder 的选择顺序；若 Finder 未位于前台、没有文件、选择的不是普通文件，给出可理解的反馈，不能错误读取旧选择。
- 推荐先评估通过 Apple Events / Finder scripting bridge 获取选中项；按实际情况请求 Automation 权限并提供清楚的设置说明。若采用 AppleScript，应稳妥处理带空格、中文、特殊字符的 POSIX 路径，并避免 shell 注入。
- 不使用私有 API，不使用键盘事件劫持的方式重写 `Space`，不尝试强制接管 MP4/MOV 系统 Quick Look 优先级。
- 支持拖放视频到窗口、通过“打开文件…”选择多个文件，作为 Finder 自动化权限受限时的替代入口。

### 2.2 单文件增强预览
- 使用 AVFoundation / AVPlayer 播放选定视频：播放暂停、静音、进度拖动，显示加载及播放失败状态。
- 同窗口显示：文件名/路径、HDR 分类、原始 transfer 值、color primaries、matrix、bit depth、chroma subsampling、codec、profile（若可用）、宽高、实际帧率、码率、时长、容器、文件大小、相机制造商/型号（存在元数据时）。
- 支持返回批量列表、通过列表切换视频；`Esc` 关闭当前预览或从单文件页返回列表，行为一致。
- 原始 HDR 播放链路应尽量避免错误色彩变换；需要在支持 HDR 的 Mac/屏幕上验证实际显示。禁止以视觉效果代替元数据判定。

### 2.3 多文件批量窗口
- macOS 原生表格，至少包含：文件名、HDR 分类、Transfer、色域、位深、色度采样、编码、分辨率、帧率、码率、时长。
- 支持按列排序、搜索文件名、HDR 类型过滤（HLG / PQ / SDR / 未知）、可调整列宽及选择显示列，记忆窗口与列表偏好。
- 顶部统计总数和每种类型数；如果一个选集混有多类，明确显示构成，并可快速过滤不同于主流类别的素材（不将其自动认定为故障）。
- 双击任意行进入单文件预览；返回时保留原有排序、过滤、滚动位置。
- 支持复制所选行的 TSV 文本，以及导出 CSV（UTF-8，合理处理引号、逗号、换行；建议带 BOM 作为 Excel 中文兼容选项）。
- 支持一次至少 200 个常见 MP4/MOV 文件：列表先显示文件名，再增量加载元数据；显示进度；有限并发（初始可配置 2–4）；允许取消；关闭窗口取消剩余任务；避免同时解码所有视频。
- 混选图片、文件夹、不可识别媒体时只处理支持的视频，并汇总跳过数量/原因；单条失败不阻塞其他文件。

## 3. HDR 类型判定（最高优先级）

使用 ffprobe 输出的**视频流元数据**作为首要判定依据，不从后缀、bit depth、色域或画面视觉风格猜测。建议读取 `color_transfer`、`color_primaries`、`color_space`、`pix_fmt`、`bits_per_raw_sample`、`codec_name`、`profile`、`width`、`height`、`avg_frame_rate`、`r_frame_rate`、`bit_rate` 等字段；读取文件/格式层面的 duration、size、tags。用 JSON 输出并结构化解析，禁止依赖随版本变化的纯文本打印。

| ffprobe `color_transfer` | 应显示分类 | 备注 |
|---|---|---|
| `arib-std-b67` | **HLG** | HLG HDR 传递函数 |
| `smpte2084` | **PQ** | PQ / ST 2084 传递函数 |
| `bt709` | **SDR（标记）** | 表示 Rec.709 传递标签；展示原始标签 |
| `iec61966-2-1` | **SDR（标记）** | 按标准传递标签显示 |
| 缺失、`unknown`、`reserved` | **未知** | 不得自动写成 SDR |
| 其他任意值（例如特定 Log） | **其他/未知** | 展示原始值，不错误归为 SDR |

**必须注意：**
- HLG 与 PQ 是不同传递函数；“HLG-PQ”不是此项目中的独立标准类别。如文件由 HLG 转换到 PQ，当前只依据**转换后的编码流标签**判别；不声称可以还原拍摄历史。
- BT.2020 不等于 HLG；10bit 不等于 HDR；BT.709 色彩原色也不必然意味着不是 Log。
- Sony S-Log/Nikon N-Log 相机拍摄曲线可能仅存于厂商私有 metadata；首版不保证恢复实际机内曲线，但必须保留原始字段、明确局限。
- 如果标记互相矛盾（例如 PQ transfer 与非常规 primaries），可额外显示“标签需核实”，不要擅自纠正。
- ffprobe 不能证明文件标签一定正确。产品文案应写“根据视频文件标记识别”。

## 4. 技术架构建议

- **语言/UI**：Swift + SwiftUI，macOS 原生菜单栏应用及窗口；根据最低支持的 macOS 版本选择 `MenuBarExtra` / `NSStatusItem`。
- **播放器**：AVFoundation `AVPlayer`，包装在 SwiftUI 视图；支持加载错误及不支持格式的提示。
- **视频检测**：`ffprobe` 通过 `Process` 执行，用 `-v error -show_streams -show_format -of json` 或精简 JSON；解析视频主流，优先选择实际画面视频流而非封面 attached picture。
- **依赖部署**：不能只假定用户安装 Homebrew。先实现开发机通过 `brew install ffmpeg` 工作；发布方案需决定合规打包 ffprobe（注意许可证及签名/公证）或首启提示安装并配置二进制路径。
- **异步任务**：Swift Concurrency，任务取消和并发限制；对 ffprobe 执行设置合理超时、错误捕获；统一日志。
- **本地缓存**：文件 URL + 大小 + 修改时间（必要时其他稳健标识）为键；检测元数据缓存可持久化并可清除；文件变更后必须失效。
- **文件访问**：注意 App Sandbox / Automation / Finder / 安全作用域书签之间的约束；在实现前验证选中文件获取、Process 执行、文件读取及签名之间的兼容性。不要未经测试声称可从沙盒内直接运行任意二进制。
- **工程管理**：优先 Xcode 工程；若使用 XcodeGen/Swift Package 建工程，README 写明生成步骤；提供 Debug 与 Release 配置。

## 5. 性能、可靠性、隐私

- 所有媒体分析本地完成，无账户系统、不上传视频或元数据。
- 解析元数据时避免完整解码视频；首屏优先显示文件名、分类和重要列。
- 单个视频分析失败在表格显示具体错误，不影响其他文件。
- 用户可手动重新分析、刷新缓存、取消扫描。
- 所有路径安全传参给 `Process.arguments`；严禁拼 shell 命令；注意非 ASCII 文件名和外接盘。
- 不修改原视频、文件时间戳或元数据。

## 6. UI/交互规范

- UI 风格遵循当前 macOS 原生浅色/深色设计，合理使用系统色和语义状态色；不用夸张的警告视觉表示“格式不同”。
- 单文件模式顶部为播放器，底部/侧边为结构化参数；HLG、PQ、SDR、未知状态清晰可辨，色彩标签在文字上也必须明确。
- 批量模式以信息密度较高、支持横向滚动的表格为主；顶部统计区 + 搜索筛选；底部显示进度与错误数量。
- 窗口尺寸合理，记忆位置与列宽；支持键盘导航、VoiceOver 基础可访问性。
- `Esc` 行为一致；不要把 `Space` 重新绑定为增强预览。

## 8. 验收标准与测试矩阵

### 必须通过的场景
1. Finder 单选 `MP4`，`Option + Space` 打开单文件窗口，能显示参数并播放。
2. Finder 多选 `MP4 + MOV`，`Option + Space` 打开同一批量表格；实际显示文件总数与各类统计。
3. HLG 样本 `color_transfer=arib-std-b67` → HLG。
4. PQ 样本 `color_transfer=smpte2084` → PQ。
5. Rec.709 transfer 样本 → SDR（标记）。
6. transfer 缺失样本 → 未知，不能误判为 SDR。
7. 文件混合、中文文件名、路径含空格、外接硬盘、无权限文件、损坏视频，应正确处理或报告失败。
8. 批量 200 文件可逐步显示进度，操作响应正常，可取消，单文件失败不影响全局。
9. 列排序、HDR 筛选、导出 CSV 与复制到表格软件正常。
10. Finder `Space` 在应用运行中、关闭增强窗口后、禁用热键后、退出应用后，始终是系统原生 Quick Look。
11. 快捷键冲突与 Finder Automation 权限拒绝有明确反馈和替代入口。

### 验证方式
- 单元测试覆盖 transfer 分类逻辑、未知/缺失、FFprobe JSON 解析、CSV 转义和缓存失效。
- 集成测试用实际 Sony 与 Nikon MP4/MOV 样本，记录相机型号、原始素材拍摄设置、ffprobe 检测值和界面显示。
- 在真实 macOS 设备上测试 Finder 自动化权限、全局快捷键、签名应用、HDR 播放行为。
- 不具备真实相机样本时，先用 ffmpeg 合成带明确色彩标签的视频做逻辑测试，但不能替代 Sony/Nikon 真机素材验证。

## 9. 已知风险 / 决策记录

- **原生 Quick Look 接管不可靠**：因此正式选择独立热键增强窗口，系统 `Space` 保持原样。
- **Finder 多选文件读取**：可能需要 Automation/TCC 权限；应先做 PoC 再确定正式方式。
- **FFprobe 打包及沙盒**：决定应用分发难度；必须实际验证，不可在设计时忽略。
- **标签与拍摄曲线不同**：本工具首要识别视频当前标记的 HLG/PQ/SDR，不保证恢复相机机内所有色彩设定。
- **HDR 显示准确性**：参数识别与视觉 HDR 输出分开验收。
- **快捷键冲突**：默认 `Option + Space`，必须允许修改，必要时提示系统或其他应用占用。
